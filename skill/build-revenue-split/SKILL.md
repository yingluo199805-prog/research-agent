# Build Revenue Split

每家公司一个工作簿，三张表：`XX三表`(利润表+资产负债表+现金流量表) / `XX附注底稿`(年报附注明细+人数，按年存放) / `收入分配拆分`(复刻比亚迪三段结构，细项全部公式链接前两表)。

> **使用者完整分步指南见 `WORKFLOW.md`**（准备数据 → 跑已配置公司 / 新增公司 4 步 → 复核清单 → 特例处理）。下面是要点速览。

## 使用流程 Workflow

### 运行环境（本机 macOS，2026-09 起）
- 只依赖 Python 3.9 + openpyxl + PyMuPDF(fitz)；**不需要 pdftotext / LibreOffice**：年报转文本用 `scripts/pdf_text.py`（有 pdftotext 时自动优先用），勾稽校验用纯 Python 的 `recon_py`（附注合计 vs 三表 / 供应商 residual / 口径残差）。产物公式不带缓存值，Excel 打开时自动计算。
- **工作根目录**：环境变量 `REVENUE_SPLIT_BASE`，或命令行 `--base <目录>`，默认 `<仓库>/outputs/收入分配`（已 gitignore）。三表导出文件夹、年报文件夹、产物 `XX A股.xlsx` 都放在根目录下；年报文本缓存在 `<根目录>/_年报文本/`。
- 所有脚本在 `scripts/` 目录下运行：`cd skill/build-revenue-split/scripts`。

### 你需要先准备的原始数据
1. **三表**：该公司利润表、资产负债表、现金流量表三个单表（数据端如 iFinD/Choice 导出的 `.xlsx`，"普通报表"），放进根目录下一个文件夹（如 `华域汽车2015-2025三表`）。
2. **年报**：该公司历年年度报告 PDF，放进一个文件夹（如 `长城2015-2025年报`），文件名前缀含发布日 `YYYY-MM-DD：`。A 股取**简体**年报（H 股 IFRS 繁体版走 h_share 规则）。

### H 股先判会计准则

H 股不要只按上市地套规则。先从年报"编制基准/遵例声明/会计准则"判断：

- **HKFRS/IFRS 原生**（如吉利、零跑）：读 `references/h_share_revenue_split_rules.md`，用按性质披露的员工福利、折旧摊销、融资成本、所得税等直接填桶。
- **US GAAP 主报表**（如蔚来、理想、小鹏 2024 年报）：默认用 US GAAP 主报表，IFRS 对账只作审阅/可选调整；员工薪酬先找完整 employee compensation/payroll，再找固定提存/社保/公积金等法定福利，并与股份支付合并为"已披露员工薪酬"；不用现金流硬凑，供应商 residual 吸收未拆人工。

已固化的 H 股公司：

```bash
python3 run_h_share_batch.py 吉利 小鹏 理想 零跑 小米     # 小米=2018-2025 八年，IFRS，含投资公允价值变动/优先股公允价值变动特殊桶
```

**年报获取与文本层**：港交所披露易的标题检索接口可直接列出某只股票全部「年度報告」直链——
`https://www1.hkexnews.hk/search/titleSearchServlet.do?...&stockId=<内部id>&t1code=40000&t2code=40100&lang=ZH`（内部 id 从
`https://www1.hkexnews.hk/ncms/script/eds/activestock_sehk_c.json` 按股票代码查），`lang=EN` 取英文版。部分港股中文 PDF（小米 2020、2023-2025）
字体无 Unicode 映射、文本层乱码，**读数改用英文版同页**（数字一致），截图底稿也用英文版；先用 PyMuPDF 抽一页看是否乱码再决定。

新增 H 股公司时，在 `scripts/run_h_share_batch.py` 复制吉利配置，补 `src_rows`、`note_rows`、`note_data`、单位换算；生成器为 `scripts/gen_h_share_revenue_split.py`。

### A 股流程

### 情形一：已配置过的 10 家（长城/长安/赛力斯/江淮/上汽/广汽/潍柴动力/宇通客车/华域汽车/万向钱潮）—— 一条命令

```bash
python3 run_v2_batch.py 华域汽车     # 单家（约 15 秒，含 12 份年报转文本）
python3 run_v2_batch.py             # 全部 10 家
```
脚本自动：年报转文本 → 解析附注 → 自动抽专业构成人数 → 建 `XX附注底稿`+`收入分配拆分` → 纯 Python 勾稽校验（终端逐年打印：销售/管理/研发附注合计 vs 三表、供应商占比、口径残差；有 LibreOffice 时再做重算校验）。
**注意：会覆盖根目录下同名工作簿里的 `附注底稿` 与 `收入分配拆分` 两张表**（三表不动）；要留原件先拷到 `_原件备份/`。
产物：`XX A股.xlsx`（含 `XX三表`/`XX附注底稿`/`收入分配拆分` 三表）。

### 情形二：新增一家公司 —— 4 步

```bash
# 1) 合并三表 -> XX三表(年份降序)，直接给文件夹/输出名（相对根目录）；终端会打印三段起始行
python3 combine_three_statements.py 华域汽车2015-2025三表 华域汽车三表 华域汽车A股.xlsx
# 2) 自动定位三表 src_rows 行号(按段+标准化标签)，段起始行用上一步打印的 section_start
python3 detect_src_rows.py "$REVENUE_SPLIT_BASE/华域汽车A股.xlsx" 华域汽车三表 '{"一、利润表":4,"二、资产负债表":66,"三、现金流量表":163}'
```
3) 在 `scripts/run_v2_batch.py` 的 `COMPANIES` 字典加一条：
   `prefix`(拼音缩写)、`folder`(年报文件夹)、`fy_map`(报告发布日前缀→财年)、`src_sheet`、`outfile`、
   `years`、`warranty_in_cogs`(质保重分类进营业成本的年份，无则 `[]`)、`headcount='auto'`、`src_rows`(上一步结果)。
   有金融子公司的，src_rows 加 `利息支出`/`手续费及佣金支出`/`汇兑收益`/`净敞口套期损益`(脚本自动并入银行/经营损失)。
```bash
# 4) 运行
python3 run_v2_batch.py 公司名
```

### 出表后人工复核（重点）
- 勾稽：每年加总应=100%（供应商=residual 已保证）；若想看口径噪声，取消隐藏附段"口径残差"行。
- 附注合计校验：销售/管理/研发费用附注合计须等于三表对应行（解析器若漏行会对不上）。
- 特例：售后(质保)年度切换、研发披露演进(lump/未单列)、单位换算、人数群体vs母公司口径——见下方规则与 a_share 规则文档。

## 14 个固定桥接科目（顺序不可改）

收入、下面各项加总、经营损失、非经营损失、业务费用、售后服务费、员工薪酬、供应商、银行、政府、
折旧、摊销、净利润-少数股东、净利润-母公司股东。
只有「业务费用」下销售/管理/研发明细行按各公司实际披露科目可变（逻辑＞形式）。

## 非协商规则（A股，详见 a_share_revenue_split_rules.md）

1. **单位**：三表多为百万元→输出亿元 `/100`（每家先读单位，勿照抄比亚迪万元/10000）。
2. **原始披露口径**：每年用当年年报，不用次年重述比较数；各费用附注合计须等于三表对应行。
3. **不重复计算**：各费用里的工资薪金/股份支付/折旧与摊销，从「业务费用」剔除，分别入员工薪酬段/附段折摊。
4. **供应商=residual（零误差，不设全局"其他"）**：`供应商=营业总收入−其余各已披露分配项`(营业成本的residual/"其他")，成本侧口径残差自然落供应商，加总恒=100%；附段"口径残差"行显示被吸收量。**勿**设顶层"其他（未分配项）"兜全局误差。
5. **制造工人=residual**：员工薪酬总额−销售−管理−研发人员薪酬；人均工资=薪酬*10000/人数(比亚迪口径)。
   人数从年报"专业构成"映射：制造=生产+其他、销售=销售、管理=财务+行政、研发=技术。只在群体口径披露时算。
6. **售后**：≤重分类前年份取销售费用"售后服务费"行；质保重分类进营业成本的年份从供应商扣减并单列。
7. **研发披露演进**：有明细→按附注；有行无明细(lump)→整笔一行、人工不拆并入制造工人；未单列→在管理费用"技术开发支出"。
8. **金融子公司**(上汽/广汽等)：收入用营业总收入、银行加利息支出+手续费支出、经营损失补资产处置/汇兑/净敞口；无金融业务自动为0。
9. **制造费用其他**(水电)未披露按营业收入×0.9%估(比亚迪即手工估)。

## 格式（参考 `公司深度报告模板（A+H）.docx` 的研报三线表，可直接贴进报告；生成器内置）

- **收入分配拆分 = 模板"表2"风格**：表头深蓝底纹 **2E3160 + 白字**、思源黑体 CN Medium 加粗居中；正文思源黑体 CN 9pt、数值右对齐；段标题(总项统计/细项拆分)浅蓝 E7E9F0+深蓝粗体；收入/加总行加粗；占比区灰字(808080)；负数红括号；三线表(标题上粗线、表头下细线、表末粗线，无竖线)；隐藏网格线；表下"数据来源…广发证券发展研究中心"行；A1/A2 内部导航。
- **附注底稿 = 模板"表1"风格**：表头浅灰 **F2F2F2** 底纹 + 深蓝 0F243E 思源黑体 CN Medium 加粗；其余同上三线表。
- **层次标注**（视觉友好）：一级(收入/加总)加粗+段色；**二级桥接科目**(经营损失/非经营损失/业务费用/售后/员工薪酬/供应商/银行/政府/折旧/摊销/净利×2)浅蓝 **E7E9F0** 底纹+深蓝加粗；**三级小计**(销售/管理/研发相关费用、制造工人及各人员职工薪酬)仅加粗；叶子明细常规。
- 数字格式：金额`#,##0.00`、占比`0.0%`、人数`#,##0`、工资`#,##0.0`。

## 验收

`run_v2_batch.py` 末尾的 `recon_py` 逐年打印三项：①销售/管理/研发费用附注合计 vs 三表对应行（带 `!` 即差 >0.5%，解析漏行或口径错）；②供应商 residual 占收入比（整车 62%–85% 区间正常）；③口径残差占收入比（越接近 0 越干净，早年披露稀疏可到 1%–2%）。
因供应商=residual，加总恒=100%，不再需要重算来验证加总。底稿"五、收入勾稽校验"区显示加总占比(=100%)；
诊断行"营业成本口径供应商(参考)/口径残差"默认隐藏，取消隐藏可看供应商吸收的成本侧口径噪声(越小越干净)。
人数/人均工资为非货币附注行，不进桥接、不进细项占比。

## 脚本（规范集，scripts/）

- `combine_three_statements.py` — 三个单表合并为 `XX三表`(年份降序)。
- `detect_src_rows.py` — 按段+标准化标签自动定位 src_rows 行号。
- `parse_notes_generic.py` — 通用附注解析(兼容 N、/N./(中文数字)、简繁体、千分位整数/小数；分类 人工/股份/折摊/售后/第三方)。
- `gen_revenue_split.py` — 核心生成器 `build(wb,cfg)`：5段结构+可变明细+其他兜底+格式。
- `run_company.py` — `build_company(cfg)`(解析→note_data→建底稿+链接→build) + `build_worksheet`(底稿+校验) + `recon_py`(纯 Python 勾稽) + `recon`(有 LibreOffice 时)。
- `_legacy/` — 长城试点期一次性脚本，仅留档。
- `common.py` — 工作根目录 / 年报文本缓存路径（`REVENUE_SPLIT_BASE` 或 `--base`）。
- `pdf_text.py` — 年报 PDF → 版面文本（pdftotext 优先，否则 PyMuPDF 按词坐标重排，效果等价）。
- `run_v2_batch.py` — 唯一配置驱动(全A股配置+转换+一键重建+纯 Python 勾稽)。
- `gen_h_share_revenue_split.py` — H 股生成器：按性质底稿+供应商 residual，适配 HKFRS/IFRS 与 US GAAP 主报表分叉。
- `run_h_share_batch.py` — H 股配置驱动；当前固化吉利/小鹏/理想/零跑试点。
- `validate_revenue_split.py` — 公式完整性与勾稽扫描。
