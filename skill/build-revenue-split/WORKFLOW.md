# build-revenue-split 使用指南（Workflow）

把一家公司的营业总收入，按年报口径分配给各利益相关方（供应商、员工、银行、政府、折旧、摊销、股东等），
复刻比亚迪模型「收入分配拆分」的三段结构与公式，加总精确=100%，输出研报格式、可直接贴进报告。

---

## 0. 产出长什么样

每家公司一个工作簿（A 股常用 `XX A股.xlsx`，H 股常用 `XXH股.xlsx`），三张表：

| 表 | 内容 |
|---|---|
| `XX三表` | 利润表 + 资产负债表 + 现金流量表（数据源，年份降序） |
| `XX附注底稿` | 从年报附注提取的费用/员工/折摊/财务收支等明细（A 股含销售/管理/研发费用和人数；H 股按性质披露，研报"表1"样式） |
| `收入分配拆分` | 主表：总项统计 / 项目占比 / 细项拆分 / 细项占比，细项全部公式链接前两表（研报"表2"样式） |

---

## 1. 准备原始数据（使用者手动）

0. **根目录**：默认 `<仓库>/outputs/收入分配`（可用环境变量 `REVENUE_SPLIT_BASE` 或各脚本的 `--base <目录>` 改）。本机 macOS 只需 Python 3.9 + openpyxl + PyMuPDF，不需要 pdftotext / LibreOffice。
1. **三表**：该公司利润表、资产负债表、现金流量表三个单表（iFinD/Choice 等数据端导出的 `.xlsx`，"普通报表"），
   放进根目录下一个文件夹（如 `华域汽车2015-2025三表/`）。
2. **年报**：该公司历年年度报告 PDF，放进一个文件夹，例如 `长城2015-2025年报/`。
   - A 股取 **简体**年报（深交所/上交所版）。H 股先读年报"编制基准/遵例声明/会计准则"，再走 `references/h_share_revenue_split_rules.md`。
   - 文件名前缀需含发布日期 `YYYY-MM-DD`（脚本据此映射财年）。

> 提示：年报 PDF 若在 OneDrive 显示"仅在线"，先右键"始终保留在此设备上"下载，否则脚本读不到。

## 2. 路径 A —— 已配置的 10 家（长城/长安/赛力斯/江淮/上汽/广汽/潍柴动力/宇通客车/华域汽车/万向钱潮）

一条命令，全自动：

```bash
cd skill/build-revenue-split/scripts
python3 run_v2_batch.py 华域汽车    # 单家
python3 run_v2_batch.py             # 全部 10 家
```

脚本会自动：年报转文本（缓存到 `<根目录>/_年报文本/`）→ 解析附注 → 抽专业构成人数 → 建底稿 + 收入分配拆分 → 纯 Python 勾稽校验。
跑完看终端逐年三列：附注合计/三表（带 `!` 为差 >0.5%）、供应商占比、口径残差（应接近 0）。
会覆盖根目录同名工作簿的 `附注底稿` / `收入分配拆分` 两张表，要留原件先拷到 `_原件备份/`。

## 3. 路径 B —— 新增一家公司（4 步）

**第 1 步：合并三表 → `XX三表`**
```bash
python3 combine_three_statements.py XX2015-2025三表 XX三表 XXA股.xlsx
```
三个参数都相对根目录；文件夹内须有 `*-利润表-*.xlsx / *-资产负债表-*.xlsx / *-现金流量表-*.xlsx`。终端打印 `section_start`（三段起始行），下一步要用。

**第 2 步：定位三表行号 `src_rows`**
```bash
python3 detect_src_rows.py "$REVENUE_SPLIT_BASE/XXA股.xlsx" XX三表 '{"一、利润表":4,"二、资产负债表":N1,"三、现金流量表":N2}'
```
（N1/N2 取上一步打印的 section_start。）脚本按标准化标签自动返回各科目行号，直接贴进配置。

**第 3 步：在 `run_v2_batch.py` 的 `COMPANIES` 加一条配置**
```python
'公司名': dict(
    prefix='py缩写', folder='XX年报文件夹', src_sheet='XX三表', outfile='XX.xlsx',
    title='XX收入分配拆分', years=list(range(起, 止+1)),
    fy_map={'2016-04-18':2015, ...},          # 报告发布日前缀 -> 财年
    warranty_in_cogs=[], warranty_vals={},     # 质保重分类进营业成本的年份(无则空)
    headcount='auto',                          # 自动抽专业构成人数(母公司口径年份自动剔除)
    src_rows={...},                            # 第2步结果
),
```
有金融子公司的（利润表有利息收入/利息支出），`src_rows` 加 `利息支出`/`手续费及佣金支出`/`汇兑收益`/`净敞口套期损益`，
脚本会自动：收入用营业总收入、利息手续费支出并入银行、资产处置/汇兑/净敞口并入经营损失。

**第 4 步：运行**
```bash
python3 run_v2_batch.py 公司名
```

## 4. 出表后人工复核清单

- **勾稽**：每年加总 = 100%（供应商=residual 已保证）。口径残差终端已打印；也可在 Excel 里取消隐藏附段"口径残差(已并入供应商)"行。
- **附注合计**：销售/管理/研发费用附注合计须 = 三表对应行（终端每年打印 `附注/三表`，带 `!` 的年份要回年报查解析漏行）。
- **人数**：PyMuPDF 与 pdftotext 对"专业构成"表的抓取偶有差异（长安 2022 管理人数：新跑 4313 对，原件 1028 漏了管理人员行），人数只影响人均工资参考行，不进桥接。
- **单位**：三表多为百万元 → 输出亿元（脚本 `/100`）；若三表是万元/亿元需改 `unit_div`。
- **售后**：质保计入销售费用的年份取"售后服务费"行；重分类进营业成本的年份从供应商扣减并单列（配 `warranty_in_cogs`）。
- **研发披露演进**：有明细→按附注；有行无明细(lump)→整笔一行、人工并入制造工人；未单列→在管理费用"技术开发支出"。
- **人数口径**：仅当专业构成是"群体口径"才算人均工资；母公司口径（构成合计 ≪ 在职合计，如上汽）自动留空。人均工资为近似参考（费用工资按职能、人数按专业构成，口径不完全对应，底稿已备注）。

## 5. 路径 C —— H 股公司

H 股不是一个单一会计口径，先判准则：

- **HKFRS/IFRS 原生**：如吉利、零跑。优先抽"雇员福利开支"、"折旧及摊销"、"融资成本"、"所得税"等按性质项目。
- **US GAAP 主报表**：如蔚来、理想、小鹏 2024 年报。默认使用 US GAAP 主报表，IFRS 对账仅作审阅/可选调整；若员工福利总额未完整披露，继续查固定提存/社保/住房公积金等法定福利，并与股份支付合并为"已披露员工薪酬"；不用现金流硬凑完整员工薪酬。

已固化试点：

```bash
cd skill/build-revenue-split/scripts
python3 run_h_share_batch.py 吉利 小鹏 理想 零跑     # 同样读 REVENUE_SPLIT_BASE / --base
```

新增 H 股公司：

1. 合并或准备 `XX三表`，确认单位（百万元、千元等）和年份列。
2. 从年报抽会计准则、收入/净利/所得税/融资成本/利息收入、员工福利、股份支付、折旧摊销、研发/销售/行政费用等。
3. 在 `run_h_share_batch.py` 复制吉利配置，补 `src_rows`、`note_rows`、`note_data`、`src_unit_div`、`note_unit_div`。
4. 运行后检查供应商 residual 是否异常，并在表下注明"未拆人工/折摊/业务费用是否被 residual 吸收"。

## 6. 背后逻辑（一句话）

营业总收入 = 供应商 + 员工 + 银行 + 政府 + 折旧 + 摊销 + 股东(净利) + 业务费用 + 售后 − 经营/非经营其他。
营业成本在利润表只有一行、A 股附注不按性质拆它，所以"制造工人薪酬""制造端折旧摊销"靠现金流量表/资产负债表抠出，
单独归给员工/折旧/摊销；抠不干净的成本侧口径差并入供应商(residual)，故加总恒=100%，不设无意义的全局"其他"。

## 7. 详细规则与脚本

- 完整规则：`references/a_share_revenue_split_rules.md`（A股）、`references/h_share_revenue_split_rules.md`（H股）。
- 脚本：`combine_three_statements.py` / `detect_src_rows.py` / `parse_notes_generic.py` / `extract_headcount.py`
  / `gen_revenue_split.py`(A股核心生成器) / `run_company.py` / `run_v2_batch.py`(A股配置驱动)
  / `gen_h_share_revenue_split.py`(H股生成器) / `run_h_share_batch.py`(H股配置驱动) / `validate_revenue_split.py`。
- 格式参照：`公司深度报告模板（A+H）.docx` 的"表1/表2"研报三线表。
