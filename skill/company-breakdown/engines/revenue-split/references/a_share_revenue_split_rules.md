# A股「收入分配拆分」实操规则（长城跑通后固化）

把营业（总）收入分配给各利益相关方。严格复刻比亚迪模型『XX收入分配拆分』结构，按各公司
实际披露科目展开明细（**逻辑＞形式**），收入勾稽差目标 < 0.5%。

## 1. 表结构（5 段，复刻比亚迪）

1. **总项统计**（14 个固定桥接科目，VLOOKUP 按标签取细项区，行可变也不怕）
2. **项目占比**（各桥接科目 / 收入）
3. **细项拆分**（公式引用三表 + 附注硬编码明细，本段是数据源）
4. **占比明细**（镜像细项 / 收入）
5. **附**：销售/管理/研发费用里的折旧摊销 → 间接费用折摊合计（供应商公式引用）

14 个固定桥接科目（顺序固定，**不要改**）：收入、下面各项加总、经营损失、非经营损失、
业务费用、售后服务费、员工薪酬、供应商、银行、政府、折旧、摊销、净利润-少数股东、净利润-母公司股东。

**供应商=residual（零误差，不设全局"其他"）**：`供应商=营业总收入−其余各已披露分配项`。
供应商本就是"营业成本−已披露的制造人工/折摊/制造费用其他/售后＝给供应商的钱"，即营业成本这一上一级的
residual／"其他"。**不要**设一个顶层"其他（未分配项）"去兜全局误差（没有含义）；成本侧口径残差
（数据端"营业总成本"约0.3%未拆明细、折摊现金流口径vs成本费用口径差、职工薪酬应付变动+现金+股份的时点差）
自然落进供应商。各费用明细的"其他"行已兜住费用内未单列项（合计对得上三表）。
附段保留"营业成本口径供应商（参考）"与"口径残差（已并入供应商）=供应商−参考"两行，显示被吸收的差(越小越干净)。
加总恒=营业总收入＝**100%**。

唯一可变的是「业务费用」下 **销售相关/管理相关/研发相关费用** 的明细行——按各公司各年实际
披露科目取并集，blank where not disclosed。生成器 `scripts/gen_revenue_split.py` 已据此参数化。

## 2. 单位换算

读三表单位（A股普通报表多为**百万元**），输出统一**亿元**。百万→亿 **/100**。
比亚迪三表是万元 → /10000；不要照抄比亚迪的换算因子，每家先读单位再定。
生成器对每个三表引用统一加 `/unit_div` 并用 `IFERROR(...,0)` 包裹（兼容 "--"）。

## 3. 用「原始披露口径」，不用次年重述比较数

三表数据端（如 Choice/iFinD 普通报表）按**每年当年年报原始披露**取值。提取附注明细时，
**只用该年自己那份年报的当年列**，绝不用次年年报里的"上年（已重述）"比较数——重述会与三表对不上。
（长城 2023 销售费用：2023 年报原始 8285.38；2024 年报重述为 7286.41。三表用 8285.38。）

校验：每年 销售/管理/研发费用 附注「合计」必须等于三表对应行（误差≈0），否则口径错了。

## 4. 不重复计算（关键）

各费用附注里的 **工资薪金 / 股份支付费用 / 折旧与摊销** 必须从「业务费用（给第三方的钱）」桶里
剔除，分别归入：
- 工资薪金 → 员工薪酬段对应人员（销售/管理/研发人员职工薪酬）
- 股份支付费用 → 对应人员股份支付
- 折旧与摊销 → 附段（销售/管理/研发费用里的折旧摊销）→ 间接费摊合计

剩下的才是「业务费用」第三方明细。校验：某段第三方明细 + 该段人员薪酬 + 该段股份 + 该段折摊
= 该费用附注合计。

## 5. 员工薪酬与制造工人

- 员工薪酬总额 = (应付职工薪酬_期末 − 期初 + 现金流量表"支付给职工现金") / 单位 + 销管研股份支付。
  （注：该总额在勾稽里会与"供应商"抵消，故其估计误差不影响收入勾稽。）
- **制造工人薪酬 = 员工薪酬总额 − 销售 − 管理 − 研发人员职工薪酬**（residual，任何公司都不单独披露）。
- 规则：**某年/某段人员薪酬只要披露了就单拆出来**；**没披露时才并入制造工人 residual**。

## 6. 售后服务费（质保/三包）——年度切换

售后是独立桥接科目（"给客户预备的钱"）。注意会计政策切换：
- 保证类质保**计入销售费用**的年份：从销售费用附注"售后服务费"行取，作售后桶；
  此时**不**从供应商扣减（warranty_in_cogs=False）。
- 保证类质保**重分类进营业成本**的年份（长城自 2024 起，提前执行新解释）：销售费用附注里
  没有售后行了，从重分类金额/预计负债计提取数作售后桶，并**从供应商扣减**（warranty_in_cogs=True，
  对应比亚迪模板某些预测年 `-售后` 的处理）。
- 逐年判断该年原始年报里售后在哪。

## 7. 研发披露演进（A股典型）

- **未单独列报年**（如长城 2014–2017）：研发在管理费用里（"技术开发支出"行），利润表研发费用="--"。
  → 不另设研发桶；技术开发支出作为管理相关费用的一个明细行（含其人工，无法拆，可接受）。
- **有研发利润表行但无明细附注年**（lump，如长城 2018–2021）：整笔研发费用（取三表研发费用行）放
  一行"研发费用（未单独披露明细）"；研发人工不单拆（并入制造工人，符合第 5 条）。
- **有明细附注年**（长城 2022+）：按附注科目展开，工资/股份/折摊照第 4 条剔除。

## 8. 制造费用其他（水电等）——手工估

比亚迪该行确为**手工硬编码估值**（15/15/20/30/50/75/80…，约占营业收入 0.7%–1.2%，均值≈0.9%）。
未披露的同业按 **营业收入 × ~0.9%** 估（生成器 `mfg_other_pct=0.009`）。
注意：这只在"供应商↔业务费用"两桶间重分类，**不影响收入勾稽差**。

## 9. 金融子公司（上汽/广汽/长城/比亚迪等都有，必查）

有汽车金融/财务公司的车企，利润表"营业总收入"含**利息收入+手续费及佣金收入**，"营业总成本"含
**利息支出+手续费及佣金支出**。处理：
- **收入用「营业总收入」**（不是营业收入），把金融业务收入纳入分母。
- **银行桶 = 财务费用 + 利息支出 + 手续费及佣金支出**（后两者给资金提供方）。
- 经营损失段补上 **资产处置收益**（独立列报，常被漏）。
- 这三处对无金融业务公司自动为 0（那几行 "--"），**通用、不需特判**。
- 长城实证：加此规则后 2019（分拆年，金融收入大）由 +0.85% → 0.00%，2019–2025 全部精确归零。

## 11. 验收

- `run_v2_batch.py` 末尾 `recon_py`（纯 Python）逐年打印：销售/管理/研发附注合计 vs 三表、供应商占比、口径残差；有 LibreOffice 时再重算读「收入(细项39)」vs「加总(细项40)」。
- 近年（数据完整、披露详细）应接近 0；早年披露稀疏/金融子公司口径噪声可放宽并注明。
- 公式整洁、数字格式、冻结窗格、可滚动；细项区年份列与三表列方向对应正确。

## 细项提取清单（按年报目录定位，提高效率）

**A. 三表(数据端 xlsx)自动取**（脚本 detect_src_rows 按标签定位行号）：营业总收入、营业收入、
营业成本、利息支出/手续费及佣金支出(有金融子公司时)、税金及附加、财务费用、公允价值变动收益、
投资收益、资产处置收益、汇兑收益/净敞口套期损益(有则取)、资产减值损失、信用减值损失、其他收益、
营业外收入/支出、所得税费用、归母净利润、少数股东损益、应付职工薪酬(资产负债表)、支付给职工现金
(现金流量表)、固定资产折旧/投资性房地产折旧/使用权资产折旧/无形资产摊销/长期待摊费用摊销(现金流量表补充资料)。

**B. 年报附注手工取**（通过目录关键词定位，不读全文）：
1. **销售费用** 附注 → 各第三方科目 + 工资薪金 + 股份支付 + 折旧与摊销（+售后服务费如列示）
2. **管理费用** 附注 → 同上（早年研发未单列时含"技术开发支出"）
3. **研发费用** 附注 → 同上（无明细年=整笔一行；未单列年=并入管理费用）
4. **预计负债(产品质量保证)** 附注 → 售后/质保（质保重分类进营业成本的年份用）
5. **员工情况/专业构成**（公司治理或董事会报告章节）→ 生产/销售/技术/财务/行政/其他 人数

目录定位关键词：`销售费用`、`管理费用`、`研发费用`、`预计负债`、`专业构成`/`员工情况`。

## 人员数量与人均工资（比亚迪口径）

从"专业构成"映射人员数量：**制造工人=生产+其他**（与制造工人薪酬residual口径一致）、**销售=销售**、
**管理=财务+行政**、**研发=技术或研发**。人均工资按比亚迪公式：`工资(万元/人)=对应人员职工薪酬(亿元)*10000/人数`
（销售/管理/研发用含股份支付的薪酬合计行；制造用residual薪酬行）。人数/工资为附注行，不进收入桥接。
脚本 extract_headcount.py 自动抽取并剔除母公司口径年份（构成合计远小于在职合计的，如上汽，留空不算工资）。
**口径提醒（底稿已备注）**：费用工资按职能、人数按专业构成，两者口径不完全对应（管理人数=财务+行政可能小于
管理费用工资覆盖面；"其他人员"默认并入制造工人），个别职能人均工资可能偏高/偏低，仅作近似参考。

## 附注底稿 + 公式链接（可追溯）

每家公司工作簿建三张表：①`XX三表` ②`XX附注底稿`（提取的全部附注明细+人数，按年存放，单位亿元/人，
注明来源与原始披露口径）③`收入分配拆分`。**收入分配拆分的细项不硬编码**，统一公式链接：附注项
`=IFERROR('XX附注底稿'!<col><row>,0)`，三表项 `=IFERROR(XX三表!<col><row>/100,0)`。便于核对与更新。

## 格式统一（参考 `公司深度报告模板（A+H）.docx` 研报三线表，可直接贴进报告）

- **收入分配拆分=模板"表2"**：表头深蓝底纹 **2E3160 + 白字**、思源黑体 CN Medium 加粗居中；正文思源黑体 CN 9pt、
  数值右对齐；段标题浅蓝 E7E9F0+深蓝粗体；收入/加总行加粗；占比区灰字 808080；负数红括号；
  三线表(标题上粗线/表头下细线/表末粗线、无竖线)；隐藏网格线；表下"数据来源…广发证券发展研究中心"行；A1/A2 内部导航。
- **附注底稿=模板"表1"**：表头浅灰 **F2F2F2** + 深蓝 0F243E 思源黑体 CN Medium 加粗；其余同三线表。
- 数字格式：金额 `#,##0.00`、占比 `0.0%`、人数 `#,##0`、人均工资 `#,##0.0`。
- 均由 gen_revenue_split.build()（收入分配拆分）与 run_company.build_worksheet()（底稿）内置生成。

## 工作流（脚本）

1. `scripts/pdf_text.py`（pdftotext -layout 或 PyMuPDF 词坐标重排）→ 文本；从目录/附注定位 销售/管理/研发费用、税金、职工薪酬、
   预计负债(质保)、折旧摊销 等表（**不读全文**）。
2. 解析附注 → 结构化 note_data（参考 `scripts/parse_changcheng_notes.py` 的分类逻辑：
   工资薪金/股份支付/折旧摊销/售后/第三方）。
3. 配置 cfg（三表名、年份列、单位、src_rows、各段明细科目并集、note_data、warranty_in_cogs、
   mfg_other_pct）→ 调 `scripts/gen_revenue_split.py: build()`。
4. `recon_py` 勾稽校验（附注合计 vs 三表逐年精确相等；口径残差 < 0.5%，早年可放宽并注明）。
